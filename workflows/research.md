# 产品研究工作流

## 概述

执行结构化的产品研究——市场、竞品、用户、技术趋势——生成有据可查的研究报告。

## 前置条件

- 用户提供了研究主题
- 明确研究范围（深度、广度、格式）

## 执行步骤

### 步骤 0：定义研究问题

与用户确认研究范围：

1. **研究什么？**
   - 竞品分析：识别和深度分析竞品
   - 市场研究：TAM/SAM/SOM 估算
   - 用户研究：用户画像、痛点、行为模式
   - 技术趋势：技术栈评估、架构模式

2. **多深？**
   - 快速扫描（30 分钟级）：3-5 个主要发现
   - 标准研究（1-2 小时级）：结构化报告
   - 深度研究（3+ 小时级）：多来源交叉验证

3. **什么格式？**
   - 结构化报告（默认，使用 RESEARCH.md 模板）
   - 简要汇报
   - 演讲/幻灯片提纲

### 步骤 1：信息收集

**1.1 Wiki 搜索**（如有 llm-wiki-skill）：
- 搜索已有知识库中的相关实体和概念
- 识别知识空白 → 优先研究

**1.2 Web 搜索**：
- 使用 WebSearch 进行多轮搜索
- 竞品搜索：`"{product} competitors"` `"{行业} 市场规模"`
- 用户研究：`"{目标用户} 痛点"` `"{行业} 用户调研"`
- 市场数据：`"{行业} market size 2025 2026"` `"{领域} trends"`

**1.3 深度挖掘**（标准/深度研究）：
- 使用 WebFetch 读取关键来源的完整内容
- 提取数据、引用、方法论

### 步骤 2：分析综合

**竞品分析框架**：
| 维度 | 竞品 A | 竞品 B | 竞品 C | 本产品定位 |
|------|--------|--------|--------|------------|
| 目标用户 | | | | |
| 核心功能 | | | | |
| 定价模式 | | | | |
| GTM 渠道 | | | | |
| 优势 | | | | |
| 劣势 | | | | |
| 差异化机会 | | | | |

**市场分析框架**：
- TAM（总可寻址市场）
- SAM（可服务市场）
- SOM（可获得市场）
- 增长率
- 关键趋势

**用户分析框架**：
- 用户画像（JTBD、痛点、收益）
- 用户旅程（认知 → 考虑 → 购买 → 使用 → 推荐）
- 行为模式

### 步骤 3：生成报告

遵循 `templates/RESEARCH.md` 模板：

1. **执行摘要**（1-3 段）
2. **研究问题**（我们想了解什么）
3. **方法论**（怎么研究的）
4. **主要发现**（数据驱动的结论）
5. **竞品/市场/用户详细分析**
6. **关键洞察**（超越数据的理解）
7. **建议**（可执行的行动项）
8. **来源**（所有引用的 URL 和文件）

### 步骤 4：知识结晶（可选）

如有 llm-wiki-skill：
- 将关键发现写入 wiki（实体、概念）
- 将竞品信息结晶为实体页面
- 将市场数据结晶为概念页面

## 关键规则

- 所有数据标注来源（URL 或文件引用）
- 区分**数据**（可验证）和**洞察**（推断）
- 不要只列数据——给出"这意味着什么"
- 中文输出
